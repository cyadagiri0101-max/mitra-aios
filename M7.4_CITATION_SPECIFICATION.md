## 1. Citation Registry Model

When context is assembled, an immutable `CitationRegistry` maps each sequential reference tag (`REF-1`, `REF-2`, ..., `REF-N`) to the exact chunk and its provenance:

```typescript
export interface CitationItem {
  ref: string; // e.g. "REF-1"
  chunkId: string;
  entityType: string;
  entityId: string;
  title: string;
  projectNumber: string | null;
  authorityStatus: AuthorityStatus;
  provenance: {
    sourceId: string | null;
    sourceType: string;
    relativePath: string | null;
    sourceFile: string | null;
    sourceSheet: string | null;
    sourceRow: number | null;
    sourcePage: number | null;
  };
  matchedSnippet: string;
}
```

---

## 2. Validation & Hallucination Elimination Invariants

1. **Strict Tag Extraction:** All occurrences of `\[REF-(\d+)\]` in the generated answer are parsed.
2. **Existence Verification:** Every extracted tag must exist in the active `CitationRegistry`. If an unlisted tag (e.g. `[REF-999]`) is encountered, it is flagged as a hallucinated citation and stripped or rejected.
3. **Multi-Tenant Scoping:** Citation metadata is strictly bound to the requesting tenant's verified retrieval context.
4. **Provenance Attachment:** The client receives the complete file name, sheet name, row number, table name, and project code for every cited source.
