## 2. DTO Schema Contract Compliance

### `EngineeringAskRequestDto`
- `query` (`string`, required): Search string or engineering question.
- `topK` (`number`, optional, default 8): Number of candidate chunks.
- `filters` (`EngineeringRetrievalFilters`, optional): Metadata filters (`projectNumber`, `customer`, `machine`, `material`, `revision`).
- `includeHistorical` (`boolean`, optional, default false): Opt-in for superseded / historical records.
- `maxContextChars` (`number`, optional, default 8000): Context character budget cap.

### `EngineeringAskResponseDto`
- `query` (`string`): Echoed question.
- `answer` (`string`): Grounded natural language response containing `[REF-x]` citations or refusal advisory.
- `grounded` (`boolean`): True if synthesized strictly from verified evidence.
- `confidence` (`'HIGH' | 'MEDIUM' | 'LOW' | 'REFUSAL'`): Statistical confidence tier.
- `insufficientEvidence` (`boolean`): True if library lacks authoritative data.
- `citations` (`EngineeringCitationDto[]`): Array of canonical citations with full provenance.
- `telemetry` (`GroundingTelemetryDto`): Granular latency breakdowns and model identifiers.

## 3. API Security & Tenant Guardrail Verification

1. **Authentication:** All `/api/ekl/*` endpoints are protected with `@UseGuards(JwtAuthGuard)` and `@ApiBearerAuth()`. Unauthenticated requests receive HTTP 401.
2. **Tenant Scoping:** Controller extracts `tenantId` from authenticated JWT token (`req.user.tenantId`) or secure header. Tenant ID is injected as the first parameter to all service invocations.
3. **Debug Endpoint Protection:** `POST /api/ekl/search/debug` and `POST /api/ekl/ask/debug` cannot bypass tenant filtering. Debug payloads include intermediate scoring math only for records belonging to the authenticated tenant.
4. **Input Validation:** Malformed JSON bodies or excessively large inputs are validated and rejected before pipeline execution.
