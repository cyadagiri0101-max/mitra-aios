# M7.2 — Engineering Normalization Architecture
## Canonical Semantic Normalization Model for Engineering Data
**Milestone:** `M7.2`  
**Status:** Certified Architecture  
**Module:** `src/modules/engineering-library/normalization`

---

## 1. Normalization Principles

1. **Human-Readable Semantic Representation:**
   - Raw database records and JSON blobs are transformed into structured, human-readable text blocks that maximize semantic embedding quality.
   - Column keys are translated into domain-specific terms (e.g. `mold_name` $\rightarrow$ `Mold / Tool Name`).

2. **Strict Preservation of Table Headers:**
   - For all tabular data (Bills of Materials, process planning sequences, cycle time benchmarks, component details), the complete Markdown column header is embedded directly into every chunk.
   - Column semantics are never lost through arbitrary row truncation.

3. **Complete Coordinate & Provenance Preservation:**
   - Normalized records retain the original `tenantId`, `sourceId`, `sourceType`, `entityType`, `entityId`, `relativePath`, `sourceFile`, `sourceSheet`, `sourceRow`, `sourcePage`, `authorityStatus`, and `revision`.

4. **Zero Data Fabrication:**
   - Missing fields are marked as `'N/A'` or omitted from metadata without inventing artificial engineering values.
