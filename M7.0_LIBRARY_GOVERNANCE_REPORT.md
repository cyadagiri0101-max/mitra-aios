## 4. Scanner Design & Path Governance
- Configurable environment variable: `MITRA_ENGINEERING_LIBRARY_PATH` (defaults to `D:\Mitra3.0\MitraEngineeringLibrary`).
- Strict validation: checks directory existence and readability before scanning; aborts gracefully with an error report if the path is invalid.
- Strict Read-Only Guarantee: Scanner uses read streams and read-only directory iteration. Zero write operations are performed against the source library.

---

## 5. Classification Rules
- `STRUCTURED_DATABASE`: SQLite database files (`database/mekb.sqlite`).
- `MASTER_WORKBOOK`: Master project workbooks (`PL.xlsx`, `EngineeringAssetInventory.*`, `PMM_Master_Data_Library.xlsx`).
- `ENGINEERING_DOCUMENT`: Markdown specifications and data dictionaries in `docs/` or root.
- `ENGINEERING_DATA`: Excel part lists, cycle time history, process planning sheets (`BM-*.xlsx`, etc.).
- `PARSER_SOURCE`: Extraction parsers and domain schemas in `parsers/`, `models/`, `importers/`.
- `MANIFEST`: Export validation batch logs in `exports/`.
- `RUNTIME_DEPENDENCY`: Virtualenv (`.venv/`) and Node packages (`node_modules/`).
- `BINARY_RUNTIME` / `CACHE`: Compiled bytecode (`.pyc`), binary extensions (`.pyd`, `.dll`), source maps (`.map`).
- `UNKNOWN` / `EXCLUDED`: Other non-engineering file types.

---

## 6. Exclusion Rules
- Automatically filters out all 19,327 runtime dependency files residing in `.venv` and `node_modules` from knowledge ingestion eligibility.
- Isolates bytecode cache folders (`__pycache__`) and build artifacts.
- Ensures zero package noise enters the future RAG knowledge index.

## 7. Streaming SHA-256 Hashing
- Computes SHA-256 fingerprints via Node.js `crypto.createHash('sha256')` streaming pipes.
- Memory footprint remains constant ($\mathcal{O}(1)$) regardless of file size.
- Produces deterministic, collision-resistant identity hashes for every file.

---

## 8. Duplicate Detection
- Groups files sharing identical SHA-256 hashes.
- Discovered 1,033 duplicate groups across the complete vault (predominantly duplicate dependency packages and snapshot copies such as `BM-454 INDEX SHEET(1).xlsx`).
- Primary copy preserved; duplicate copies tagged with `duplicateOfHash` for transparent audit logging.

---

## 9. Revision Detection
- Detects revision candidates using suffix tokens: `RevA`, `RevB`, `(1)`, `(2)`, `_v1`.
- Grouped 7 distinct revision candidate sequences across core domain workbooks.
- Sorts candidates by timestamp to identify latest vs superseded files without destructive deletion.

## 10. Authority Model
- `AUTHORITATIVE_RELEASE`: Verified production databases, released parsers, and formal revision spreadsheets (`RevA`).
- `CURRENT_WORKING`: Active project planning matrices (`PL.xlsx`).
- `HISTORICAL_REFERENCE`: Baseline studies, gap analyses, and iteration copies (`(1)`).
- `SUPERSEDED`: Replaced base versions when formal revision exists.
- `UNKNOWN`: Excluded runtime dependencies.

## 11. Provenance Model
- Captures `sourceFile`, `relativePath`, `sha256`, `fileSize`, `lastModified`, `classification`, `authorityStatus`, `scanBatchId`, `scannerVersion`.
- Extracts domain attributes where discoverable: `projectNumber` (`BM454`), `projectPrefix` (`BM`), `customer` (`Veedol`, `ALPLA`), `documentType` (`PART_LIST_BOM`), `machine` (`SEB101`), `revision` (`RevA`).
