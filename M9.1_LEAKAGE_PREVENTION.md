# M9.1 — Data Leakage Prevention Architecture
## Temporal Cutoff Enforcement & Causality Preservation
**Milestone:** `M9.1`  
**Status:** **ENFORCED & CERTIFIED**

---

## 1. Leakage Guardrails

1. **Temporal Cutoff Boundary:** Every feature generation query accepts a strict `predictionCutoff: Date`.
2. **Strict Filtering:** All source tables (`milestones`, `work_orders`, `ncr_records`, `trial_observations`, `schedule_baselines`, `project_design_loads`) filter events strictly created on or before the cutoff timestamp ($\le \text{predictionCutoff}$).
3. **Future Event Exclusion:** Any event with `createdAt > predictionCutoff` or `actualDate > predictionCutoff` is safely discarded from feature aggregates and recorded in `futureExcludedCounts` for observability.
4. **Target Isolation:** Ground truth target extraction is strictly separated and only computed when explicitly requested for historical training datasets.
