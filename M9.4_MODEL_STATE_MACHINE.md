# M9.4 — Model Lifecycle State Machine Specification
## Governed Lifecycle Transitions & Transition Constraints
**Milestone:** `M9.4`  
**Status:** **AUTHORITATIVE**

---

## 1. State Transition Diagram

```
TRAINED
   │ (evaluateModel)
   ▼
EVALUATED
   │ (requestApproval)
   ▼
PENDING_APPROVAL ───► REJECTED (rejectModel)
   │ (approveModel)
   ▼
APPROVED
   │ (activateModel)
   ▼
 ACTIVE ───────────► RETIRED (retireModel / superseded by new activation)
   │
   └───────────────► ROLLED_BACK (rollbackModel)
```

---

## 2. Transition Guardrails

- `TRAINED -> EVALUATED`: Requires minimum sample threshold ($\ge 5$).
- `EVALUATED -> PENDING_APPROVAL`: Validates complete metric payload.
- `PENDING_APPROVAL -> APPROVED`: Records approver identity and timestamp.
- `APPROVED -> ACTIVE`: Verifies SHA-256 cryptographic artifact integrity, atomically retires prior active model in serializable transaction.
- `ACTIVE -> ROLLED_BACK`: Atomically re-activates the most recently retired champion model.
