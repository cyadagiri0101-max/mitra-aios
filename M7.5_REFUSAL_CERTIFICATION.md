## 1. Objective & Refusal Protocol

In industrial engineering environments, generating a plausible-sounding but fabricated measurement, tolerance, material grade, or machine specification can lead to catastrophic tool damage or scrap production.

MITRA enforces an absolute zero-tolerance policy against hallucination. When the engineering library lacks verified records, the system must trigger an explicit refusal advisory:

> *"The engineering library does not contain sufficient evidence to answer this reliably."*

---

## 2. Refusal Architecture & Double-Guardrail Enforcement

The pipeline employs a two-tier defense against answering out-of-scope or unverified questions:

1. **Pre-LLM Retrieval Refusal Guard:**
   - If hybrid retrieval yields 0 candidate chunks above score threshold ($0.1$), the LLM is bypassed entirely.
   - Immediate deterministic refusal response returned with `confidence: 'REFUSAL'`, `insufficientEvidence: true`, and empty citations (`[]`).

2. **In-Context Grounding & Prompt Constraint Guard:**
   - If partial chunks are retrieved (e.g. project mentions) but specific queried parameters are absent, the strict system prompt forbids general knowledge inference.
   - The model emits the standard refusal text.
   - `EngineeringCitationValidatorService` and `EngineeringPhi3GroundingService` detect the refusal phrasing, mark `confidence: 'REFUSAL'`, and ensure 0 phantom citations are attached.
