## 1. Adversarial Threat Model & Grounding Invariants

In enterprise engineering, untrusted inputs may attempt to manipulate LLM outputs by overriding system instructions, requesting fabricated specifications, bypassing citation rules, or extracting confidential tenant data.

MITRA enforces architectural invariants that the LLM cannot override:
1. **Context Priority:** System prompt explicitly defines context passages as the sole permissible source of truth.
2. **Deterministic Output Validation:** Post-generation regex and registry lookup strictly enforces citation legitimacy regardless of model generated output.
3. **Hardcoded Refusal Triggers:** If evidence is lacking, the application enforces the refusal state regardless of model compliance.

## 3. Defense-in-Depth Summary

1. **System Prompt Isolation:** User questions are strictly enclosed inside a dedicated `USER QUESTION:` block, isolated from system directives.
2. **Algorithmic Validation:** Even if an adversarial prompt succeeds in tricking the LLM into generating `[REF-999]`, the post-generation `EngineeringCitationValidatorService` strips the tag and logs a hallucination attempt.
3. **Zero Exfiltration:** The local Ollama runtime runs air-gapped without outbound network access.
