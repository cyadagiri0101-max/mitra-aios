## 1. Multi-Tenant Architectural Enforcement

MITRA enforces multi-tenancy at every tier of the Knowledge Intelligence pipeline:

```
[HTTP Request with JWT / x-tenant-id]
   │
   ▼
[EngineeringLibraryController] ──> Extracts verified `tenantId`
   │
   ├──> [Knowledge Ingestion]   ──> All chunks & documents inserted with `tenant_id`
   ├──> [Lexical Retrieval]     ──> SQL WHERE tenant_id = :tenantId
   ├──> [Vector Search]        ──> SQL WHERE tenant_id = :tenantId (pgvector cosine)
   ├──> [Hybrid Fusion (RRF)]  ──> Scoped strictly to candidates of current `tenantId`
   ├──> [Context Builder]      ──> Builds context from tenant-verified candidates only
   └──> [Phi-3 Synthesis]      ──> System prompt receives tenant-isolated context only
```

## 3. Subsystem Layer-by-Layer Verification

1. **Lexical Retrieval Layer (`EngineeringLexicalSearchService`):**
   - Query parameterized with `WHERE tenant_id = $1`.
   - Verified that PostgreSQL full-text index scan does not return records with foreign tenant IDs.

2. **Vector Retrieval Layer (`EngineeringVectorSearchService`):**
   - Cosine similarity calculation executed on dataset pre-filtered by `tenant_id`.
   - Nearest-neighbor calculations are strictly bounded to the calling tenant.

3. **Context Builder & Citation Registry (`EngineeringContextBuilderService`):**
   - Receives pre-filtered candidate array.
   - Assigns sequential `[REF-1]` tags strictly within the current request context.

4. **Model Synthesis & Output Validator (`EngineeringCitationValidatorService`):**
   - Strips or refuses any attempt to reference records outside the tenant registry.
