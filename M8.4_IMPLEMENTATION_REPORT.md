## 1. Executive Summary & Objective

Milestone **M8.4** formalizes the approved Engineering Decision corpus (M1/G5) into governed Knowledge Article draft records (M8/G12).

### Key Architectural Deliverables:
1. **Approved Decision Drafting:** Service operation `createArticleDraftFromDecision(decisionId, userId, tenantId)` converts `APPROVED` `EngineeringDecision` records into structured `KnowledgeArticle` records in `DRAFT` state.
2. **Strict Eligibility Gate:** Non-approved decisions (`DRAFT`, `SUBMITTED`, `REJECTED`, `SUPERSEDED`, `CANCELLED`) are deterministically rejected with `BadRequestException`.
3. **Idempotency & Duplicate Prevention:** Exactly ONE active root `KnowledgeArticle` (`parentArticleId = null`) is created per decision in a given tenant. Repeated requests return the existing root article.
4. **Mandatory Human Signoff:** The generated knowledge article is strictly initialized in `DRAFT` (`version = 1`, `isLatest = true`). Automated publication is forbidden; it must pass through the certified M8.2 review lifecycle.
5. **Bidirectional Provenance:** Preserves `decisionId`, `projectId`, and `tenantId` on the generated draft article.

## 2. EngineeringDecision Architecture & Lifecycle Integration

## 4. Idempotency & Revision Compatibility

- **Root Article Invariant:** If `createArticleDraftFromDecision` is invoked multiple times for the same decision, the query detects the existing root article where `decision_id = decisionId` and `parent_article_id IS NULL`, returning the existing record without creating duplicate entries.
- **Revision Compatibility:** Subsequent M8.3 revision branching (`v1` $\rightarrow$ `v2` $\rightarrow$ `v3`) remains fully functional. Because child revisions have `parentArticleId != null`, the root check cleanly distinguishes the primary root from historical revisions.
