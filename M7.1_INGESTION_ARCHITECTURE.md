# M7.1 — Knowledge Library Ingestion Architecture
## Safe, Restartable, Tenant-Aware Knowledge Synchronization Pipeline
**Milestone:** `M7.1`  
**Status:** Certified Implementation Architecture  
**Module:** `mitra-backend/src/modules/engineering-library` & `src/modules/knowledge`

---

## 1. Architectural Principles

1. **Strict Read-Only Source Access:**
   - The raw source vault (`D:\Mitra3.0\MitraEngineeringLibrary`) and `database/mekb.sqlite` are accessed using read-only streams and `DatabaseSync(..., { readOnly: true })`.
   - Zero modifications, updates, deletions, or schema changes are permitted in the source vault.

2. **Deterministic Source Identity & Multi-Tenancy:**
   - Source items are isolated by tenant via `TenantAwareService.requireTenant(tenantId)`.
   - Entity IDs in the destination `knowledge_catalog` are deterministically generated:
     $$\text{EntityId} = \text{UUIDv5}\left(\text{TenantId} : \text{Database} : \text{Table} : \text{PrimaryKey}\right)$$
     $$\text{DocumentEntityId} = \text{UUIDv5}\left(\text{TenantId} : \text{'DOC'} : \text{RelativePath} : \text{SHA256}\right)$$
   - Guarantees that identical source data mapped to the same tenant produces the exact same primary key across multiple ingestion runs.

3. **Strict Idempotency:**
   - Row-level and document-level content hashing (`sha256(JSON(row))` and `doc.sha256`).
   - If hash matches existing indexed record $\rightarrow$ `SKIPPED` (0 updates, 0 duplicates).
   - If hash changes $\rightarrow$ `UPDATED` (version updated, sourceRef refreshed).
   - If not found $\rightarrow$ `CREATED`.

4. **Outbox Batch Lifecycle:**
   - Managed by `KnowledgeIngestionBatchService`.
   - Ingestion jobs are tracked under `knowledge_ingestion_batches` and item-level steps under `knowledge_ingestion_items` (`QUEUED`, `PROCESSING`, `SUCCESS`, `SKIPPED`, `FAILED`).
   - Granular error isolation: a failure in one table or document does not abort the entire batch.

## 4. Ingestion Entities & Schema

### `knowledge_sources` Table
- `id` (UUID, Primary Key)
- `tenant_id` (UUID, Indexed)
- `source_type` (`MEKB_DATABASE`, `TECHNICAL_DOCUMENT`, `MASTER_WORKBOOK`, `PARSER_SOURCE`, `SPREADSHEET_DATA`)
- `source_file`, `relative_path`, `sha256` (Indexed with `tenant_id` unique constraint)
- `file_size`, `last_modified`, `classification`, `authority_status`, `authority_reason`
- `project_number`, `project_prefix`, `customer`, `document_type`, `machine`, `material`, `revision`
- `scanner_version`, `scan_batch_id`, `first_seen_at`, `last_seen_at`, `current_status` (`ACTIVE`, `SUPERSEDED`, `FAILED`, `ARCHIVED`)

### `knowledge_ingestion_batches` Table
- `id` (UUID, Primary Key)
- `tenant_id` (UUID, Indexed)
- `scan_batch_id` (VARCHAR)
- `started_at`, `completed_at`, `status` (`QUEUED`, `RUNNING`, `COMPLETED`, `PARTIAL`, `FAILED`, `CANCELLED`)
- `total_candidates`, `processed`, `succeeded`, `failed`, `skipped`
- `records_created`, `records_updated`

### `knowledge_ingestion_items` Table
- `id` (UUID, Primary Key)
- `batch_id` (UUID, Foreign Key to batches)
- `tenant_id` (UUID, Indexed)
- `source_identifier`, `source_type`, `status` (`QUEUED`, `PROCESSING`, `SUCCESS`, `SKIPPED`, `FAILED`)
- `records_created`, `records_updated`, `records_skipped`, `error_code`, `error_message`
