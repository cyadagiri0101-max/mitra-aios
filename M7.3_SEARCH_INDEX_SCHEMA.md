# M7.3 — Search Index Schema & Physical Query Optimization
## PostgreSQL FTS, pgvector Cosine Index & Composite Filters
**Milestone:** `M7.3`  
**Status:** Certified Schema  
**Tables:** `knowledge_chunks`, `knowledge_embeddings`

---

## 1. Physical Index Architecture

```sql
-- 1. Unique Content Hash per Tenant
CREATE UNIQUE INDEX "IDX_knowledge_chunks_tenant_content_hash" 
ON "knowledge_chunks" ("tenant_id", "content_hash");

-- 2. Unique Coordinate Index
CREATE UNIQUE INDEX "IDX_knowledge_chunks_tenant_entity_ordinal" 
ON "knowledge_chunks" ("tenant_id", "entity_id", "chunk_type", "chunk_ordinal");

-- 3. Project-scoped Lookup Index
CREATE INDEX "IDX_knowledge_chunks_tenant_project" 
ON "knowledge_chunks" ("tenant_id", "project_number");

-- 4. Entity Type Lookup Index
CREATE INDEX "IDX_knowledge_chunks_tenant_entity_type" 
ON "knowledge_chunks" ("tenant_id", "entity_type");

-- 5. Authority & Revision Composite Index
CREATE INDEX "IDX_knowledge_chunks_tenant_authority" 
ON "knowledge_chunks" ("tenant_id", "authority_status", "revision");

-- 6. pgvector HNSW / IVFFLAT Cosine Index
CREATE INDEX "IDX_knowledge_embeddings_vector_cosine" 
ON "knowledge_embeddings" USING ivfflat ("embedding" vector_cosine_ops)
WITH (lists = 100);
```

---

## 2. Query Execution Performance

- **Tenant Scoping:** Applied in initial `WHERE` clause before text scoring or vector distance calculation.
- **pgvector Cosine Distance:** Uses native `<=>` operator returning similarity scores scaled to $[0, 1]$.
