# M7.2 — Engineering Chunking Specification
## Deterministic Chunking, Identity & Content Hashing Rules
**Milestone:** `M7.2`  
**Status:** Certified Specification  
**Module:** `src/modules/engineering-library/chunking`

---

## 1. Deterministic Chunk Identity Model

Every chunk receives a globally unique, deterministic UUIDv5 identifier computed from its provenance coordinates:

$$\text{ChunkId} = \text{UUIDv5}\left(\text{tenantId} : \text{sourceId} : \text{entityType} : \text{entityId} : \text{chunkType} : \text{chunkOrdinal}\right)$$

### Properties
- **Collision-free:** Different tenants or entities produce distinct UUIDs.
- **Repeatable:** Identical input coordinates yield the exact same primary key across multiple runs.
- **Traceable:** Directly decodable to its source entity and ordinal position.

---

## 2. Content Hashing & Idempotency Protocol

To achieve 100% idempotency, every chunk calculates a SHA-256 hash across its normalized text and structured metadata:

$$\text{ContentHash} = \text{SHA256}\left(\text{tenantId} : \text{normalizedText.trim()} : \text{JSON.stringify(metadata)}\right)$$

### Ingestion Logic
1. **Lookup by `(tenantId, contentHash)`:**
   - Match found $\rightarrow$ `SKIPPED` (0 updates, 0 database writes).
2. **Lookup by `(tenantId, entityId, chunkType, chunkOrdinal)`:**
   - Coordinate found, but hash differs $\rightarrow$ `UPDATED` (resets `embeddingStatus` to `PENDING`).
3. **No match:**
   - $\rightarrow$ `CREATED` (status `PENDING`).

---

## 3. Sub-Chunking Rules for Large Technical Documents

- **Maximum Chunk Size:** 2,500 characters (~500 tokens).
- **Split Boundaries:** Markdown double newline (`\n\n`), section headers (`#`, `##`), or logical table boundaries.
- **Context Prefix:** When documents are split into multiple chunks ($N > 1$), all secondary chunks retain a header prefix:
  `[Document Context: <Title> | Path: <RelativePath>]`
- **Table Integrity:** Tables are never split mid-row; column headers remain intact.
