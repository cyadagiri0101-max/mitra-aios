## 1. Executive Summary

Milestone **M8.4** bridges the formal `EngineeringDecision` corpus (M1/G5) with the governed `KnowledgeArticle` lifecycle (M8/G12).

- **`EngineeringDecision` (Source of Truth):**
  - Managed by `EngineeringDecisionService` (`src/modules/engineering-decisions/services/engineering-decision.service.ts`).
  - Lifecycle: `DRAFT` $\rightarrow$ `SUBMITTED` $\rightarrow$ `APPROVED` | `REJECTED` $\rightarrow$ `SUPERSEDED`; `CANCELLED`.
  - Captures: `decisionNumber`, `title`, `decisionType`, `description`, `context`, `optionsConsidered`, `selectedOption`, `rationale`, `decision`, `decisionDate`, `decisionOwnerId`, `approvedBy`, `approvedAt`, `projectId`, `relatedEntityType`, `relatedEntityId`.
- **`KnowledgeArticle` (Governed Human Knowledge):**
  - M8.1 domain fields: `decision_id`, `project_id`, `version`, `is_latest`, `parent_article_id`, `superseded_by_id`.
  - M8.2 state machine: `DRAFT` $\rightarrow$ `UNDER_REVIEW` $\rightarrow$ `PUBLISHED` (human review gate mandatory; direct publication forbidden).
  - M8.3 revision engine: Monotonic versioning, immutable published records, atomic supersession.

## 3. Invariants & Protection Rules

1. **Approved Decision Only:** Only `EngineeringDecision` records with `status === DecisionStatus.APPROVED` can be drafted into a `KnowledgeArticle`.
2. **Draft State Mandatory:** Generated articles MUST start in `DRAFT` state (`status = ArticleStatus.DRAFT`, `version = 1`, `isLatest = true`). Automated publication is strictly forbidden.
3. **Idempotency & Duplicate Prevention:** Exactly ONE active root `KnowledgeArticle` may represent a given `decisionId` per tenant. Subsequent requests return the existing root article.
4. **Tenant Isolation:** Cross-tenant decision references are strictly rejected (`decision.tenantId === requested tenantId`).
5. **Separation of Concerns:** `EngineeringDecision` remains the immutable decision log. `KnowledgeArticle` becomes the governed human-facing knowledge document.
